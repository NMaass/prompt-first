# Requirements

Use this skill when a mission begins, when learner feedback changes the intended product, or when implementation exposes an unresolved product decision.

Read `mission.json` and current conversation. Build the smallest contract that preserves the learner's intent while allowing reversible implementation to continue.

A good contract captures:

- target user;
- problem and desired outcome;
- observable acceptance criteria;
- relevant quality requirements;
- constraints;
- consequential actions;
- assumptions and unresolved decisions.

Do not turn the contract into a feature wishlist. Prefer outcomes and observable behavior.

Publish the current contract with `studio-contract`. Update it when the learner changes intent. Do not wait for formal approval before reversible work.
